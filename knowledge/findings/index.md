# Findings

<!-- GA-GENERATED:index -->

- [AppMenu's signed-out watcher races the delete dialog's navigation to /signin](appmenu-signout-watcher-race.md) - After an account is deleted, AppMenu's watcher and the dialog both navigate; the app ends on /signin only because the dialog's replace is issued last, not because a guard says so.
- [Secret-shaped values committed to git](committed-secret-candidates.md) - The inventory scan flagged two whole files and five lines as possible secrets; the docs say they are demo or public values, but nobody has confirmed each one.
- [errorCode and isOwnerId are duplicated across two functions, and the errorCode copies differ](functions-helpers-duplicated.md) - functions/src/deleteUserData.ts copies isOwnerId and errorCode from reminders.ts; the two errorCode copies disagree on numeric gRPC codes, so the same Firestore failure logs differently.
- [Cancelling Google's page before it loads leaves the Google button busy](google-redirect-cancel-leaves-button-busy.md) - The back-forward cache reset covers a restored page, but if the user cancels before Google's page commits, no pageshow fires and the button stays busy; not verified on a device.
- [The route guard compares paths exactly, so /SignIn and /signin/ escape its sets](guard-compares-paths-exactly.md) - The guard's two path sets match to.path and the redirect's pathname exactly while the router is case-insensitive and non-strict, so a signed-in visit to /SignIn isn't bounced and a redirect to /signin/ isn't refused.
- [Offline, sign-out still waits for the device document to be deleted](offline-sign-out-waits-on-device-delete.md) - The sign-out hook awaits the device-document delete, which never settles offline, so Sign out from the menu spins until the connection returns, although the push token is now removed at once.
- [The developer's device received no push reminders](push-reminders-not-received.md) - With the notifications toggle on, no reminder reached the developer's device; the production function ran every 5 minutes for two days with 233 runs, all sending nothing and failing nothing, so the gap is before the send.
- [A link check that can never succeed offers Try again forever](reset-check-try-again-forever.md) - A failed check on a disabled or deleted account is shown as retryable, so Try again fails with the same answer each time.
- [The live reset code stays in the address bar and browser history](reset-code-stays-in-address-bar.md) - /reset-password leaves oobCode in the URL while the form shows, so a credential that sets the password sits in history, synced history and any pasted URL until used or expired.
- [The forgot and reset screens use sign-in's fixed-height layout, which may cut off a tall card on short viewports](reset-fixed-height-layout-short-viewports.md) - ResetPasswordView and ForgotPasswordView set a 100vh centred layout like sign-in's, not sign-up's scrolling one; the reset card is as tall as sign-up's, so its top may be unreachable on a short screen; not verified.
- [The per-account reset limit can reveal that an address has an account](reset-limit-can-reveal-account.md) - Asking repeatedly for one address ends in "Too many attempts" for a known account and in the neutral confirmation for an unknown one, unless email enumeration protection hides it; not confirmed against the live project.
- [A lost response to the password change reports the link as used, though the password is set](reset-lost-response-reports-link-used.md) - If the server sets the password but the response is lost, pressing the button again gets invalid-action-code and the screen says the link is invalid or used, sending the user for a second link they don't need.
- [After resetting one account on a device signed in as another, Sign in lands in the other account](reset-sign-in-lands-on-other-account.md) - The reset screen's Sign in and Ask for a new link go to /signin and /forgot-password, and for a signed-in visitor the guard sends /signin on to /home, which is the signed-in account's.
- [docs/SECURITY.md names a contact address in PRIVACY.md that no longer exists](security-doc-names-removed-privacy-contact.md) - The security inventory lists the contact address in PRIVACY.md among identifiers left in the repository on purpose, but PRIVACY.md is now only a pointer to /privacy and has no address.
