# Android app (TWA)

## Role

Puts the web app on the Play Store as `in.spanion.todo.twa`. It holds no app logic: it opens the site in a Trusted
Web Activity. Why this package and this tool: [decisions/android-app-bubblewrap](../decisions/android-app-bubblewrap.md).

## Stack

A Gradle project generated by Bubblewrap CLI `1.27.0` from `packages/android/twa-manifest.json`: changing the app
means editing that file and rerunning Bubblewrap, not hand-editing the generated files. Its `minSdkVersion` is
`24`, not Bubblewrap's default of 21, because androidbrowserhelper 2.7.4 declares 24 and the manifest merge fails
below it. `LauncherActivity.java` grants itself the splash image's URI before launching (Chrome 152+ drops the splash
otherwise, GoogleChrome/android-browser-helper#623); `twa:update` leaves that file alone, but re-check it after each
regeneration. It targets API 36, falls
back to Custom Tabs, never a WebView, because Google refuses sign-in in a WebView, and delegates notifications to the
browser. Building, signing and publishing are in [operations/play-store-release](../operations/play-store-release.md).

## Entry points

- `packages/android/twa-manifest.json`: the package id, the host it opens, `startUrl`, `fallbackType` and the
  signing-key fingerprints.
- `packages/android/app/src/main/java/in/spanion/todo/twa/LauncherActivity.java`.
- The site proves it owns the app through `public/.well-known/assetlinks.json`, served as `application/json` by
  `firebase.json`. It names only the new package, with the developer's existing upload key's SHA-256 fingerprint
  (the key PWABuilder made in 2024, reused). Play's app-signing key fingerprint is added after the first upload;
  until then a Play-installed app, which Play signs, shows a URL bar (spec W1).
